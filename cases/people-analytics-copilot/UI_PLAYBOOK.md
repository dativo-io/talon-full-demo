# People Analytics — browser-first demonstration

**Audience:** presenter or reviewer who prefers clicking through real applications rather than watching terminal commands.

This guide has **the same proof sequence and evidence** as the [terminal-first playbook](PRESENTER_COMMANDS.md). Nothing is mocked in the operator console: each action invokes the corresponding allowlisted Docker/Talon command and shows actual output and exit code. The browser is a convenience layer, **not** the policy enforcement mechanism.

## 1. What you will open

| Browser tab | Purpose | Security boundary |
|---|---|---|
| [Workforce Intelligence](http://127.0.0.1:8501/) — port **8501** | Department filters, DuckDB-powered charts, guided or live AI chat, simulated forbidden-tool probe routed through Talon | Unprivileged AI app; no Docker permission or HR warehouse volume |
| [Operator Proof Console](http://127.0.0.1:8502/) — port **8502** | Guided before/after checks, backend counters, network inspection, policy files, signed evidence | **Separate authenticated local host process with Docker operator privileges**; never exposed to the AI app |

**These are not the same application.** The customer-facing AI app must **not** have the credentials, file mounts, or Docker permissions required to perform the operator's privileged BEFORE export.

### Prerequisites — one-time terminal setup

The UI is browser-first, but the presenter must start the trusted demo processes on an Ubuntu host. You need Docker + Compose v2, OpenSSL and a compatible Talon executable.

From the checked-out PR branch, run in **Terminal A**:

~~~bash
cd ~/demos/talon-full-demo-hr
git switch feat/people-analytics-copilot-v1
git pull --ff-only
talon version
docker compose version
bash scripts/people-analytics-isolated.sh up
~~~

This starts a deterministic **GUIDED**, non-LLM scenario. Real Talon MCP enforcement is active. The warehouse contains *fictional* employee records.

In **Terminal B** on the same trusted host, run:

~~~bash
cd ~/demos/talon-full-demo-hr
bash scripts/people-analytics-isolated.sh presenter
~~~

Keep this process running. It prints a **one-time operator token**. Treat it as a credential: don't place it in the demo prompt, URL, public screen share or source code. The token is used only in the console tab's memory.

If the host is remote, from your laptop start one SSH port forward (substitute your normal account and hostname):

~~~bash
ssh -N -L 8501:127.0.0.1:8501 -L 8502:127.0.0.1:8502 user@demo-host
~~~

Then open both local URLs above. Neither app needs a publicly reachable port. **Do not publish port 8502**, because the console executes operator-level Docker actions.

## 2. The business app — show value first (1–2 minutes)

Open **Workforce Intelligence** on port 8501. Choose a department and demonstrate that the headcount, tenure and attrition charts respond to the filter. This is a separate aggregate-only dashboard service reading DuckDB. **Normal chart reads do not traverse Talon.**

In the assistant panel, use the example prompt "Which departments have the highest attrition over the last six months?" The standard mode is labelled **GUIDED · NO LLM**; it retrieves actual aggregates via Talon's MCP proxy and formats a deterministic answer. Show the Talon allow receipt, but do not describe the prose as generated by a model.

If the operator console is not started, its link will not work. That does not change Talon's running MCP policy in the business app.

## 3. Unlock the operator proof console

Open port 8502 or use **Open the 7-stage presenter proof console** from the dashboard header.

Paste the one-time operator token from Terminal B into the password field and select **Unlock**. The console should show:

- An explanation distinguishing privileged BEFORE, explicit RESET, and isolated AFTER
- An ordered set of seven proof stages (plus service readiness)
- A progress indicator reflecting **real command exit codes**, not an assertion that an external security audit passed
- Each action's **Run check**, **View exact terminal command**, **Copy command**, and expandable actual stdout/stderr

Use **Go to next incomplete check** to move between checks. Commands don't run automatically; sensitive BEFORE and RESET actions require additional confirmation.

For a terminal demonstration of any action, copy its displayed command, after setting up the \`dc\` shortcut shown in the console. The shell and UI actions use exactly the same Docker containers and underlying verification functions.

## 4. Follow seven stages and show the evidence

| Stage | What to click | What the reviewer should see |
|---|---|---|
| **1. Direct access** | **Privileged direct employee export**, then **Read independent HR execution counters** | A fictional employee name/salary; export count increases. This call **bypasses Talon** |
| **2. Measurement reset** | **Explicitly reset synthetic HR counters** | All counters become zero. This **does not change any permission** |
| **3. Deployment perimeter** | Inspect AI/Talon/HR networks and app mounts, then **Verify network isolation and working dashboard** | UI cannot access the HR DuckDB volume or direct private backend; aggregate dashboard still works. **Docker** enforces separation |
| **4. Effective boundaries** | Inspect agent + proxy policy, then **Discover available tools through Talon** | Only \`hr_attrition_summary\`, \`hr_headcount_summary\`, \`hr_tenure_summary\` appear |
| **5. Authorized analytics** | **Execute approved aggregate tool; inspect receipt** | Real DuckDB aggregate result plus \`decision=allow\`, committed evidence ID |
| **6. Forbidden operation** | **Force employee export through Talon**, then **Verify backend export remained at zero** | \`decision=deny\`, \`provenance=not_dispatched\`, committed receipt; HR backend shows **zero export executions since Stage 2** |
| **7. Independent evidence** | **Export signed presenter session**, then **Verify exported signatures** | CLI reports no invalid records, missing signatures or parse errors |

**Do not skip Stage 2.** A BEFORE export is *supposed* to succeed. If you leave its counter nonzero and then run the AFTER check, you will produce a misleading result. The operator resets only counters, never data or permissions.

The last two stages are especially persuasive: the console shows **unmodified Talon responses**, then queries the independent HR execution counter and invokes Talon's real audit verification. Signed evidence captures actions Talon actually saw, **not** the earlier direct call.

### Check what the UI can and cannot claim

A green **Exit 0 · command succeeded** means the executable returned successfully. The actual stdout/stderr is the source of truth for the observation. A green progress bar counts successful commands within the **current browser tab**; it does not replace the independent signed-audit check.

The negative test deliberately forces a forbidden call through Talon. It proves **preventive MCP governance**; it is *not* an LLM trying to misuse employee data on its own.

## 5. Optional — show natural-language AI with a real provider

Before promising a real-AI demonstration, validate the provider path from a terminal in a separate, isolated loopback run:

~~~bash
# Stop other processes occupying the required ports before the separate smoke.
read -rs -p "OpenAI API key: " OPENAI_API_KEY; echo
export OPENAI_API_KEY
bash scripts/test-people-analytics-real-provider.sh
~~~

Only after that succeeds, enable **LIVE** in the Docker demo:

~~~bash
bash scripts/people-analytics-isolated.sh live
~~~

Reload port 8501. The mode badge must read **LIVE AI · TALON**. Ask for aggregate attrition and inspect the returned Talon receipts. External provider calls are billable. The LIVE path has **not** been validated with an actual model provider in regular CI. If provider smoke fails, use GUIDED and say so.

The provider key is passed to Talon's initialization container via environment variables before storage in Talon's vault. A privileged Docker operator may inspect container environments. Use a trusted demo host, fictional HR data, and a disposable provider credential.

## 6. Troubleshooting and cleanup

- **Console says Locked:** paste the token printed by Terminal B; verify port 8502 is forwarded if remote. The token does not appear in the repository or URLs.
- **Console shows a failed check:** expand actual output; inspect the displayed exact command. You can reproduce it in a host terminal as documented in [PRESENTER_COMMANDS.md](PRESENTER_COMMANDS.md).
- **Business UI says counters unavailable:** expected in isolated mode; independent HR counters belong in the operator console, not the unprivileged browser app.
- **Dashboard fails:** inspect \`bash scripts/people-analytics-isolated.sh logs\` on the host and check the Docker Compose containers.
- **Progress resets when refreshing:** intentional; the proof records live in Talon, not in your browser's progress state. Re-run only the checks you need. Avoid repeating the BEFORE action after the reset.
- **Port conflict:** stop a previously running demo instance; don't expose ports publicly or kill unrelated processes.

Stop the operator console with **Ctrl+C in Terminal B**. Then stop the isolated services with:

~~~bash
bash scripts/people-analytics-isolated.sh down
~~~

For a fresh start, \`bash scripts/people-analytics-isolated.sh reset\` destroys **synthetic** HR and Talon demo volumes. It is not needed for ordinary cleanup.
